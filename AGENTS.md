# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, Cursor, etc.) when working with code in this repository. It is the single source of truth for project instructions; `CLAUDE.md` only points here.

## What this is

LingoPop for Windows: a tray AI translator (translate, fix grammar, rewrite, explain, screen translate, magic) built with Tauri v2 and an OS-agnostic Rust core. It is a sibling of the macOS app `slucheninov/lingopop` and shares its persisted formats. Design spec: [docs/superpowers/specs/2026-10-30-lingopop-app-design.md](docs/superpowers/specs/2026-10-30-lingopop-app-design.md).

## Layout

Each task appends its own modules here in the same commit.

- `Cargo.toml` - workspace (`resolver = "2"`, members `crates/*` and `app/src-tauri`, shared package fields, version `0.1.0`)
- `rust-toolchain.toml`, `rustfmt.toml` - toolchain (honoured only by CI locally, no `rustup` on the dev machine) and formatting
- `.gitignore`, `.gitattributes` (`eol=lf`), `LICENSE`, `README.md`, `AGENTS.md`, `CLAUDE.md`
- `scripts/check-core-deps.sh` - guard: `lingopop-core` must not depend on OS or UI crates, nor on a platform TLS stack (`native-tls`, `openssl*`, `aws-lc-*`, `rustls-native-certs`, `rustls-platform-verifier`, `system-configuration*`) and must not have `tokio` as a direct normal dependency (dev-dependency or transitive via reqwest is fine); a second guard fails when `lingopop-orchestrator` has a direct normal dependency on `tauri*`, `windows*`, `winapi`, `objc*`, `cocoa`, `core-foundation*` or `core-graphics`
- `.github/workflows/ci.yml` - CI (`core` matrix on Windows and macOS, aggregator job `build-and-test`)
- `crates/lingopop-core/Cargo.toml`, `crates/lingopop-core/src/lib.rs` - the OS-agnostic core crate (`VERSION`)
- `crates/lingopop-core/src/operation.rs` - `AIOperation` (frozen raw values, English names)
- `crates/lingopop-core/src/provider.rs` - `ProviderType`, `ProviderField`, static `ProviderCapabilities`, `ProviderConnectionSettings` (hand-written `Debug`: `base_url` / `referer` go through `errors::debug_url`), `default_providers()`
- `crates/lingopop-core/src/languages.rs` - `LanguageInfo`, the 28-row `ALL` table, `quick_list()`, `info()`, `code()` / `deepl_code()` / `microsoft_code()`, `name_for_detect_code()` (ISO 639-3 detector codes)

- `crates/lingopop-core/src/serde_uuid.rs` - `#[serde(with = ...)]` UUID codec (uppercase on write, any case on read)
- `crates/lingopop-core/src/records.rs` - `HistoryEntry`, `UsageRecord` (provider/operation kept as raw strings so unknown values survive a rewrite; typed accessors)
- `crates/lingopop-core/src/envelope.rs` - `MergeableEnvelope<T>` v2 file format (`version`/`items`/`deleted`/`clearedBefore`, legacy bare array and UTF-8 BOM read), `Tombstone`, `Mergeable`, pure `merged` / `pruned` / `mark_deleted` / `mark_cleared` (90-day tombstone retention; uuid case-insensitive, linear time)

- `crates/lingopop-core/src/paths.rs` - `DataPaths` (file names in the injected data dir: `settings.json`, `history.json`, `usage.json`, `secrets.dat`; the core never computes the dir)
- `crates/lingopop-core/src/store_common.rs` - crate-private `EnvelopeFile<T>`: the one implementation of the store load rule (missing / blank / BOM / legacy / quarantine of corrupt files) and persist rule (prune tombstones, atomic write, then swap memory)
- `crates/lingopop-core/src/history_store.rs` - `HistoryStore` (`history.json`, newest first, cap on `add` / `trim`, `remove` tombstones, `clear` watermark, cap overflow never tombstoned)

Order: elevated foreground = `InputBlocked` before anything is touched; wait for the user's modifiers to be released (synthesize key-ups only after the timeout) BEFORE the snapshot, so a foreign write during the wait is part of the snapshot and is never clobbered by an older one; snapshot (failure aborts) and a log of skipped known-format names / unsaved format ids; copy; poll the clipboard SEQUENCE NUMBER (no Swift sentinel marker: Windows bumps it on every write, even identical text), with a final check at the deadline, unchanged = `None` and the clipboard is never written; the text read at the end is returned only when the sequence number is still the one last observed (otherwise it may be a foreign write: `None`); settle across "empty, then set" double bumps (two consecutive agreeing sequence reads, then, while the text is still empty or blank and the 100 ms settle budget is not spent, keep polling sequence and text every 10 ms; `None` only when the budget is exhausted without non-blank text); empty / whitespace / non-text = `None`. Elevation is checked explicitly because UIPI drops our input silently while `SendInput` still reports success, so the call alone cannot detect it. - `app/src-tauri/src/main.rs`, `src/lib.rs` - `windows_subsystem = "windows"` in release; `run()`: data dir, logger, single-instance plugin FIRST (a second launch exits), command handler, `setup` (platform `native()`, `state::load`, the hidden `popup` window, `ReqwestTransport` + `OperationRunner::new(ProviderRegistry::standard(), ..)`, `Deps`, `Orchestrator` in managed `ShellState`, dismiss forwarder, hotkeys, tray), `RunEvent::ExitRequested { code: None }` -> `prevent_exit` (closing windows never quits a tray app; Quit calls `app.exit(0)`)
- `app/src-tauri/src/paths.rs` - `data_dir()` (+ pure `data_dir_from(base)`): `%APPDATA%\LingoPop` on Windows (the spec's fixed folder, NOT Tauri's `app_data_dir()`), `~/Library/Application Support/LingoPop-dev` on macOS dev, fallback `./LingoPop-data` when the variable is missing
- `app/src-tauri/src/state.rs` - `ShellConfig: ConfigSource` (Settings + SecretStore behind std Mutexes, `snapshot()` = `ConfigSnapshot::from_parts`), `ShellStores: Persist` (History / Usage stores behind Mutexes, write errors logged without user text) and `load`: settings default on a read error, secrets fall back to an empty store on a path that never exists (`secrets.unavailable`; Phase 4a never writes secrets), history / usage `None` (persistence skipped, the real file untouched) when they fail to open
- `app/src-tauri/src/popup_shell.rs` - `ShellPopup: PopupView` over the hidden `popup` window: `show_at` emits `popup://model` (view-model JSON) and shows via the platform `NoActivateWindow::show_at(WindowHandle(hwnd), rect)`; `update` only emits; `hide` = platform `hide`; `is_visible` is an `AtomicBool`. NEVER Tauri `show()` / `set_focus()` on Windows (the macOS dev build falls back to `show()` only when the platform returns `Unsupported`). The size is kept in LOGICAL px and converted with the scale of the monitor under the origin at every show; `resized(w, h)` re-applies a visible popup and returns the physical rect; `ready()` re-emits a model that arrived before the webview listened. These calls run on async workers under the orchestrator's session mutex and never wait on the main thread
- `app/src-tauri/src/commands.rs` - `ShellState`, `PopupAction` (`#[serde(tag = "type", rename_all = "camelCase")]`: `copy`, `replace`, `retry {provider}`, `rewrite`, `explain`, `retranslate {language}`, `translateOcr {provider}`, `close`; providers use their frozen raw values) and the commands `popup_action` (spawned on the runtime, the webview does not wait for a run), `popup_resized` (logical -> `ShellPopup::resized` -> `Orchestrator::popup_resized`), `popup_ready`. RULE: every command is `async`, so none runs on the main thread, which must stay free to service the cross-thread `SetWindowPos`
- `app/src-tauri/src/hotkeys.rs` - `install(orchestrator, hotkeys)`, called from `setup` on the event-loop thread: `GlobalHotkeyService::new()` is kept in a `thread_local!` on that thread (it is `!Send`, never moved); registers `settings.hotkeys` for every operation EXCEPT Screen Translate (no region picker until Phase 4b); a conflict / invalid chord is logged (operation name + chord, no user text) and startup continues; a std forwarder thread maps `HotkeyId -> AIOperation` and spawns `Orchestrator::trigger`. `tauri-plugin-global-shortcut` is not used. Re-registration (4b) goes through `AppHandle::run_on_main_thread`
- `app/src-tauri/src/dismiss.rs`, `src/picker.rs`, `src/tray.rs`, `src/logging.rs` - `spawn_forwarder` (std thread over `platform.dismiss.events()` -> `Orchestrator::dismissed`), `NoPicker: RegionPicker` (`Ok(None)`, the overlay is Phase 4b), the tray (icon, tooltip "LingoPop", one item "Quit LingoPop"), and a small file logger (`lingopop.log` in the data dir, rotated once to `lingopop.log.1` at 1 MB; `lingopop*` targets at Debug in debug builds / Info in release, everything else Warn+ so no HTTP client can log a URL carrying text; stdout copy in debug builds) instead of `tauri-plugin-log`

### Mac fixtures

The fixtures under `crates/lingopop-core/tests/fixtures/mac/` come from the real macOS models, not from Rust. macOS with the Swift toolchain only; the mac repo is read from `$LINGOPOP_MAC_REPO` (default `~/Works/slava/lingo-pop`) and never modified.

```bash
./scripts/mac-fixtures/run.sh generate    # regenerate fixtures + SOURCE.txt (only when the mac models change)
cargo test -p lingopop-core --test mac_fixtures
# manual gate before changing the history / usage / secrets formats (Rust-written files must decode in Swift):
cargo test -p lingopop-core --test mac_fixtures -- --ignored write_rust_outputs_for_swift_check
./scripts/mac-fixtures/run.sh check target/mac-roundtrip
```

`check <dir>` decodes `history.json`, `usage.json` and `secrets.payload.json` with the Swift models, skips absent files and exits 1 on a decode failure or when all three are absent. The roundtrip directory defaults to `target/mac-roundtrip` (override with `LINGOPOP_ROUNDTRIP_DIR`).

## Rules

- The core stays OS-agnostic: no `windows`, `winapi`, `tauri*`, `objc*`, `cocoa`, `core-foundation*` dependencies, and `#![forbid(unsafe_code)]`. `scripts/check-core-deps.sh` enforces it in CI.
- Persisted raw values and the date/UUID encoding are frozen and must never be renamed or changed:
  - `ProviderType`: `"Claude"`, `"OpenAI"`, `"Gemini"`, `"Grok"`, `"Google (Free)"`, `"Google Translate"`, `"DeepL"`, `"Microsoft Translator"`.
  - `AIOperation`: `"translate"`, `"grammarFix"`, `"rewrite"`, `"explain"`, `"screenTranslate"`, `"magic"`.
  - Dates are JSON numbers: `f64` seconds since 2001-01-01T00:00:00Z (add 978307200 for Unix epoch).
  - UUIDs are written uppercase and read case-insensitively.
  - `history.json` / `usage.json` use the envelope v2 `{ "version": 2, "items": [...], "deleted": [{"id","at"}], "clearedBefore": <date> }`.
  - UI and error text use `display_name()`, never the raw value.
- Prompt texts are copied verbatim from the macOS `Core/PromptBuilder.swift` (token `{{targetLanguage}}`) and are never localized.
- No external network in tests; loopback mock servers in `tests/` are allowed. Live tests are `#[ignore]` and never run in CI. See "Live provider checks".
- No secrets or API keys in logs, fixtures or issues.
- `unsafe` is allowed only under `crates/lingopop-platform/src/windows/` and `src/macos/` (crate-level `deny(unsafe_code)`, `// SAFETY:` on every block); core stays `forbid(unsafe_code)`.
- `DevPlaintextProtector` is dev-only and compiled out on Windows (`#[cfg(not(windows))]`); shipped builds use `WindowsProtector` (DPAPI).

## Platform checks

- Default run (`cargo test --workspace --locked`, every CI leg): pure algorithm tests on fakes, hotkey mapping, clamp, OCR selection, plus on Windows the DPAPI tests, `native_bundle_constructs` and the `ocr_*` tests (skip-aware: no language pack prints `skipped: OcrUnavailable`). On macOS the monitors test of the dev implementation runs; `mac_clipboard_roundtrip_text` is `#[ignore]` because it touches the real pasteboard.
- Rule: any test that needs an interactive desktop (real clipboard, foreground window, cursor, hotkey delivery, screen capture) is `#[ignore = "needs interactive desktop"]` and lives in `tests/windows_smoke.rs`. All hotkey desktop tests stay ignored together with the other desktop tests.
- CI: the Windows leg runs them in a dedicated required step, `cargo test -p lingopop-platform --locked --test desktop_probe --test windows_smoke -- --ignored --nocapture --test-threads=1`. The probe on `windows-latest` printed `PROBE interactive=true clipboard=ok hotkey=ok sendinput=1` (WinSta0, one 1024x768 monitor). If the runner image ever loses its desktop, re-mark the step `continue-on-error: true`.
- By hand on a Windows machine with a desktop: `cargo test -p lingopop-platform --test windows_smoke -- --ignored --nocapture --test-threads=1`.
- macOS dev implementation: `send_copy` needs Accessibility permission (System Settings, Privacy & Security, Accessibility, for the terminal or the built app); without it `send_copy` returns `InputBlocked`.
- Not verified by CI (manual checklist, Phase 4 `docs/testing/manual-checklist.md`): mixed-DPI and multi-monitor capture, taskbar on every edge, elevated target (expect `InputBlocked`), menu-bar activation after a synthesized Alt key-up (Notepad, Word), console apps where Ctrl+C does not copy, Excel / Word clipboard formats after a capture, OCR with no language pack.

## Live provider checks

The live tests in `crates/lingopop-core/tests/live.rs` send real requests to the provider APIs. The owner runs them on a Mac with `scripts/live-tests.sh` before a release or after a provider change. They are never run in CI (all `#[ignore]`), and a plain `cargo test` does not run them. A provider whose variable is unset is skipped (`skipped: <VAR> not set`); with no variables set no request is sent.

| Test | Environment variable(s) |
|---|---|
| `live_claude`, `live_openai`, `live_gemini`, `live_grok` | `LINGOPOP_LIVE_CLAUDE_KEY`, `LINGOPOP_LIVE_OPENAI_KEY`, `LINGOPOP_LIVE_GEMINI_KEY`, `LINGOPOP_LIVE_GROK_KEY` |
| `live_google_cloud` | `LINGOPOP_LIVE_GOOGLE_CLOUD_KEY` (+ optional `LINGOPOP_LIVE_GOOGLE_CLOUD_REFERER`) |
| `live_deepl` | `LINGOPOP_LIVE_DEEPL_KEY` |
| `live_microsoft` | `LINGOPOP_LIVE_MICROSOFT_KEY` (+ optional `LINGOPOP_LIVE_MICROSOFT_REGION`) |
| `live_google_free` | `LINGOPOP_LIVE_GOOGLE_FREE=1` (unofficial endpoint, no key) |

Optional model override: `LINGOPOP_LIVE_<P>_MODEL` with `<P>` = `CLAUDE`, `OPENAI`, `GEMINI`, `GROK`, `GOOGLE_CLOUD`; the default is the `default_providers()` model. Every provider translates `"Good morning, my friend."` to Ukrainian (non-empty, differs from the input, contains a Cyrillic character); the LLM providers also run GrammarFix and the vision path on `fixtures/vision/hello.png`.

- Keys are read from the environment and never printed, logged or committed, not even on failure.
- A live test that fails after a provider API change means: update the Swift-parity facts (the macOS provider sources) and the mock tests first, then the provider.
