# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, Cursor, etc.) when working with code in this repository. It is the single source of truth for project instructions; `CLAUDE.md` only points here.

## What this is

LingoPop: a tray / menu-bar AI translator (translate, fix grammar, rewrite, explain, screen translate, magic) for **Windows and macOS** from one codebase: Tauri v2, an OS-agnostic Rust core and a shared Svelte UI, with per-OS adapters in `lingopop-platform`. Releases ship an unsigned Windows portable exe and macOS arm64 / x64 dmg + zip signed with the pinned self-signed certificate on tag runs (ad hoc or Developer ID only on other runs, see `docs/RELEASING.md`) (`LingoPop.app`, the same name as the Swift app, which an install into Applications replaces); 0.2.0 is the first stable release. The cross-platform work followed the plan ([docs/superpowers/plans/2026-11-03-cross-platform.md](docs/superpowers/plans/2026-11-03-cross-platform.md), spec [docs/superpowers/specs/2026-11-03-cross-platform-design.md](docs/superpowers/specs/2026-11-03-cross-platform-design.md)). The Swift macOS app `slucheninov/lingopop` (bundle `com.lingopop.app`) is frozen and stays unchanged; this repository shares its persisted formats; the Tauri app has its own bundle id and data folder and imports nothing. Original Windows design spec: [docs/superpowers/specs/2026-10-30-lingopop-app-design.md](docs/superpowers/specs/2026-10-30-lingopop-app-design.md).

## Layout

Each task appends its own modules here in the same commit.

- `Cargo.toml` - workspace (`resolver = "2"`, members `crates/*` and `app/src-tauri`, shared package fields, version shared by every crate and the app, see "Release")
- `rust-toolchain.toml`, `rustfmt.toml` - toolchain (honoured only by CI locally, no `rustup` on the dev machine) and formatting
- `.gitignore`, `.gitattributes` (`eol=lf`), `LICENSE`, `README.md`, `AGENTS.md`, `CLAUDE.md`
- `README.md` is for people who want to try the app (badges, features, download, Windows / macOS install, Accessibility and Screen Recording grant, providers, privacy, FAQ); it has no build-from-source or test instructions (those are in `CONTRIBUTING.md` / this file). `docs/settings.md` is the user guide to every Settings tab, the tray / menu-bar menu, the popup, History and the data folder; screenshots will go to `docs/screenshots/` (the README keeps a commented placeholder list)
- `scripts/check-macos-production.sh [repo-root]` - the macOS readiness gate (POSIX bash, shellcheck-clean, text inspection plus python3-stdlib JSON path reads (no jq); exit 0 prints `macOS production readiness: ok`, otherwise each problem goes to stderr and it exits 1): (1) the `#[cfg(target_os = "macos")] pub fn native()` body in `crates/lingopop-platform/src/native.rs` must be found (a missing body fails, never a vacuous pass), must not mention `DevPlaintextProtector`, `dev_protector`, `Fake*`, `NoLastForeground`, `AlwaysGranted`, `Unsupported`, `todo!` or `unimplemented!`, and must wire `MacProtector`, `MacLoginItem`, `MacCapture`, `MacOcr`, `MacOverlay`, `MacClipboard`, `MacKeys`, `MacForeground`, `MacPermissions`, `MacPopupWindow` and `MacDismissWatcher`; (2) no old stub marker text (`screen capture on macOS`, `OCR on macOS`, `region overlay on macOS`) in the `.rs` files under `src/macos` or in `native.rs` (a Markdown note there passes, since CI skips the build for Markdown-only changes); (3) every production `.rs` reference to `DevPlaintextProtector` / `dev_protector` outside `dev_protector.rs` has `#[cfg(any(test, feature = "dev-plaintext"))]` on the line before; (4) `dev-plaintext` appears nowhere except its definition line `dev-plaintext = []` (manifests, workflows, packaging configs, `.cargo`, `app/package.json`); (5) `tauri.macos.conf.json` `identifier` and `bundle.macOS.minimumSystemVersion` read BY JSON PATH (a key at the wrong level or inside a string does not count; invalid JSON fails) and no `version` key; (6) a build COMMAND carrying `--all-features` fails, because it would enable `dev-plaintext`, in EVERY `.github/workflows/*.y*ml` and every script under `scripts/` (not `scripts/tests`, not the gate itself; so `packaging.yml` and `packaging-macos.sh` are covered). Detection is per command, not per file (python3-stdlib inside the script): a workflow `run:` value that spans lines (`>`, `>-`, `|` or a plain multi-line scalar) is NOT decoded as YAML (blank lines, indentation and folding are what a hand decoder gets wrong): on its raw, comment-stripped lines an `--all-features` is accepted only when its own physical-line command segment starts `cargo tree` or `cargo metadata` (after global options), any other occurrence fails when the block contains a build-like cargo / tauri command ANYWHERE (or the file name says it releases or packages), so `cargo tree` + blank line + `cargo build` + `--all-features` on the next line is rejected; shell scripts and one-line values use the per-command rule: backslash continuations are joined, `#` comments are dropped outside quotes (`cargo build # --all-features` is fine) and `&&` / `||` / `;` / `|` start a new command; the command fails when it is `cargo [+toolchain] [global options] build|test|clippy|run|check|bench|doc|rustc|install|bundle|tauri ...` (`cargo --color always build --all-features` counts; the values of `--color`, `-C`, `-Z`, `--config` are skipped), `tauri build|bundle`, `npm run tauri` or `npx tauri`; in a file whose NAME contains `release`, `packag`, `bundle`, `dist`, `dmg`, `notar` or `sign` any other command carrying the flag fails too, except the read-only `cargo tree|metadata|pkgid|read-manifest|locate-project|vendor|fetch`; `cargo tree --all-features` stays fine in every file, also next to a normal build. `scripts/tests/test_macos_production_gate.py` (`python3 -m unittest discover -s scripts/tests -p 'test_macos_production_gate.py'`) copies the relevant tree into a temp dir, expects the real tree and an untouched copy to pass and one intentional defect per rule (DevPlaintextProtector wiring, an enabled `dev-plaintext` feature as dependency feature / `default` / in `release.yml`, an ungated reference, a stub marker, a missing or fake-wired `native()`, a wrong identifier, a wrong minimum OS, a misplaced minimum-OS key, invalid JSON, `--all-features` in a release / packaging / otherwise-named build workflow or script, a `version` key) to fail; a comment that mentions `--all-features` passes, and so does `cargo tree --all-features` in a file that also builds (fixture `test_cargo_tree_all_features_in_a_file_that_also_builds_is_fine`; `test_a_build_on_a_continued_line_or_after_a_tree_still_fails` pins the other direction). CI runs both on the macOS `core` leg only (step `Check macOS production readiness`: shellcheck of every `scripts/*.sh`, the gate, the fixture tests; a missing shellcheck is installed with `brew install shellcheck`, never skipped); they are cheap, deterministic and OS-independent, but only the macOS leg is the one that owns the macOS build.
- `scripts/check-core-deps.sh` - guard: `lingopop-core` must not depend on OS or UI crates, nor on a platform TLS stack (`native-tls`, `openssl*`, `aws-lc-*`, `rustls-native-certs`, `rustls-platform-verifier`, `system-configuration*`) and must not have `tokio` as a direct normal dependency (dev-dependency or transitive via reqwest is fine); a second guard fails when `lingopop-orchestrator` has a direct normal dependency on `tauri*`, `windows*`, `winapi`, `objc*`, `cocoa`, `core-foundation*` or `core-graphics`
- `.github/workflows/ci.yml` - CI (job `changes` classifies the changed files with `scripts/ci-changes.py` (stdin paths, prints `code=true|false`: only a set made entirely of `.md` files other than `docs/INSTALL.md` is `false`; an empty set, a new branch or an unknown base builds; tests `scripts/tests/test_ci_changes.py`); `core` matrix on Windows and macOS runs only when `code` is true; aggregator job `build-and-test` (the required check) always reports and passes when `core` succeeded or was skipped for a docs-only change; both legs run `actions/setup-python` 3.12, the step `Check localization catalogs` = `python scripts/gen-localizations.py check` plus `python -m unittest discover -s scripts/tests -p 'test_localizations.py'` and the step `Check versions and release scripts` = `python scripts/check-version.py` plus the release-script unit tests (`test_check_version.py`, `test_release_assets.py`, `test_package_macos_mode.py`, `test_ci_changes.py`), before `Test frontend`)
- `scripts/check-version.py [--tag vX.Y.Z] [--root DIR]` - the shared version check (Python stdlib, 3.9+; `check(root, tag) -> (version | None, sorted errors)`): `Cargo.toml` `[workspace.package]` `version` (a small table-aware reader, no tomllib), `app/src-tauri/tauri.conf.json`, `app/package.json`, `app/package-lock.json` `version` and `packages[""].version` must be equal SemVer strings (pre-release allowed, no build metadata), `app/src-tauri/tauri.macos.conf.json` must not contain a `version` key at ANY level, and with `--tag` the tag must be `v<version>`; success prints only the version on stdout (workflows capture it), failure prints `error: ...` lines to stderr and exits 1. Run by CI and by every release leg; `scripts/tests/test_check_version.py` covers each mismatch on temp roots
- `release-platforms.json` - `{"macosPreview": true}`: the only release toggle. The Mac legs ALWAYS build and verify; `false` only keeps their assets off the GitHub release (then `SHA256SUMS.txt` lists only the Windows exe and `verify_assets` receives `{windows}`). It names no assets. Missing, unreadable, invalid JSON, a non-bool value or any other key = fail closed: nothing is published
- `release-signing.json` - `{"macosCertificateSha1": "<40 lowercase hex>"}`: the SHA-1 of the one self-signed macOS release certificate, pinned in the designated requirement so Accessibility / Screen Recording survive updates; `package-macos.sh` (`selfsigned`) refuses any other imported identity and checks the signed app's requirement against it. It must equal core `updates::RELEASE_CERT_SHA1` (test `release_cert_sha1_matches_release_signing_json`); next to it `updates::UPDATE_PUBLIC_KEY` is the minisign public key of the update signatures. Never rotate either (see `docs/RELEASING.md`); the private material lives only in GitHub secrets and the owner's offline backup
- `scripts/verify-release-assets.py` - the release asset contract (Python stdlib, 3.9+, runs on Linux: no dmg mount). Fixed names per platform slug: `windows-x64` = `LingoPop-<version>-windows-x64-portable.exe`, `macos-arm64` / `macos-x64` = `LingoPop-<version>-macos-<arch>.dmg` + `.zip` (aliases `windows`, `macos` = both Mac slugs). Each build leg uploads the artifact `LingoPop-<version>-<slug>` with its assets, `SHA256SUMS-<slug>.txt` and, Mac only, `signing-<slug>.txt` (`SIGNING_MODES` = `adhoc` | `selfsigned` | `developer-id`). `asset_names(version, slug)` is the UNSIGNED build set (build legs, `assemble`); `updatable_names` = the exe / the zip (the files the in-app updater installs; dmgs are never signed), `signed_asset_names` = the build set with `<asset>.minisig` right after each updatable asset, `updatable_assets(version, platforms)` = the names to sign in contract order. `verify_assets(directory, version, platforms, manifest="SHA256SUMS.txt", signed=False) -> sorted errors` (error prefix = the name without `LingoPop-<version>-`, e.g. `macos-x64.zip: executable architecture is not x86_64`): exactly the selected names (`signed=True`: the signed set, else a `.minisig` is an `unexpected file`) plus the manifest (anything else `unexpected file`), size 1 byte..1 GiB (a `.minisig` 1..4096 bytes, the updater's limit; its text check `inspect_signature`: UTF-8, LF, exactly four lines `untrusted comment: ..` / signature / `trusted comment: ..` / global signature, else `<name>.minisig: not a minisign signature`, and the trusted comment exactly `lingopop-update <asset>`, else `<name>.minisig: trusted comment does not name the asset`; the cryptographic check is the Rust tool's), strict manifest (`<64 lowercase hex>  <basename>`, LF, trailing LF, no blank line, no duplicate, every asset listed, `checksum mismatch`), the exe's PE machine is AMD64, every dmg ends in a UDIF `koly` trailer, every zip holds only `LingoPop.app/` with `Contents/Info.plist` (`CFBundleIdentifier` `app.lingopop.tauri.macos`, `CFBundleShortVersionString` = version, `LSMinimumSystemVersion` `13.0`, `LSUIElement` true), `_CodeSignature/CodeResources`, and a thin Mach-O `CFBundleExecutable` with the execute bit, the slug's architecture (a universal binary is the wrong architecture), `LC_BUILD_VERSION` minos 13.0 and `LC_CODE_SIGNATURE`. CLI `verify --version V --platforms LIST [--manifest NAME] [--signed] DIR` (used by each leg on its own staged output); the publish job's three steps (the CLI `publish` is gone): `prepare --version V --platforms-file F --artifacts DIR --out DIR --changelog F --install F --notes-out F [--require-mac-signing MODE]` = `prepare(..)`: read `release-platforms.json` (`read_release_platforms` -> `None` fails closed; `platforms_for`; `platforms_from_file`), `assemble(.., require_mac_signing)` (copy the selected assets out of each artifact directory into an EMPTY `--out`, a duplicate basename / foreign manifest entry / missing artifact / missing or disagreeing signing mode is an error, with `require_mac_signing` every SELECTED Mac leg must report exactly that mode, else `signing-<slug>.txt: <mode> is not allowed for a release (<required> required)`, a Windows-only selection is unaffected; concatenate the per-platform manifests into `SHA256SUMS.txt`), the pre-signing `verify_assets` on the unsigned set, `render_notes` (the CHANGELOG `## [<version>]` section, else `Test pre-release <version> of LingoPop.`, then the Installation part of `docs/INSTALL.md`); `updatable --version V --platforms-file F` prints `updatable_assets` one per line; `finalize --version V --platforms-file F DIR -- <command...>` = `finalize(..)`: `add_signatures_to_manifest` (APPENDS a line per existing expected `.minisig`; the asset lines stay the legs' checksums, so an asset changed after `prepare` is a `checksum mismatch`), `verify_assets(.., signed=True)` and ONLY THEN run the command once (argv list, no shell) with the signed set's paths and `SHA256SUMS.txt` appended. Result: 9 files with the Mac assets (exe, 2 dmg, 2 zip, 3 `.minisig`, manifest), 3 without. `scripts/tests/test_release_assets.py` (synthetic PE / Mach-O / zip / UDIF / minisign-shaped fixtures, a publish double counting calls; `Base.publish` = prepare, a fake signer, finalize, the workflow's order) pins the anchors `missing_mac_asset_blocks_publication`, `wrong_arch_asset_blocks_publication`, `checksum_mismatch_blocks_publication`, `malformed_release_platforms_fails_closed` and `mac_preview_false_manifest_and_platform_set`, the `Signatures` cases (missing / wrong-comment / old-version / malformed `.minisig`, a signed dmg, an asset swapped before signing) and `RequiredMacSigning` (adhoc / developer-id refused, selfsigned and Windows-only accepted); CI runs it with the version-check tests

### Owner-run Keychain test

The native test touches the login keychain, uses a throwaway service (never the app service), and deletes its item with an RAII cleanup guard. It is ignored by default. Run only when ready for Keychain prompts:

```bash
cargo test -p lingopop-platform --test macos_secrets --locked native_throwaway_keychain_roundtrip -- --ignored --exact --nocapture --test-threads=1
```

The default `macos_secrets` suite uses injected key stores and never touches the login keychain. Ad-hoc signature changes may prompt or require re-granting access; silent access is not required. The legacy file keychain may reject the accessibility attribute; the adapter first requests AfterFirstUnlockThisDeviceOnly, retries only errSecParam without that attribute, and retains synchronizable=false.

### Release

1. Bump the version to the same value in `Cargo.toml` (`[workspace.package]`), `app/src-tauri/tauri.conf.json` and `app/package.json` (plus `app/package-lock.json` via `npm install --package-lock-only --prefix app`; `Cargo.lock` updates with `cargo check --workspace`).
2. Move the CHANGELOG `Unreleased` entries into a `## [<version>] - <date>` section.
3. `python3 scripts/check-version.py` must print the new version (it also rejects a `version` key in `tauri.macos.conf.json`).
4. Merge through a PR, then push the tag `v<version>` on `main`. The `Release` workflow checks the tag against the versions, builds the portable exe and the macOS arm64 / x64 dmg + zip, verifies the combined `SHA256SUMS.txt`, uploads everything to a draft, checks the uploaded files and only then publishes the release (a pre-release when the version has a `-` part, else the Latest release), whose notes end with the Installation section of `docs/INSTALL.md`. Full procedure, signing and `release-platforms.json`: `docs/RELEASING.md`.

## Rules

- The core stays OS-agnostic: no `windows`, `winapi`, `tauri*`, `objc*`, `cocoa`, `core-foundation*` dependencies, and `#![forbid(unsafe_code)]`. `scripts/check-core-deps.sh` enforces it in CI.
- Persisted raw values and the date/UUID encoding are frozen and must never be renamed or changed:
  - `ProviderType`: `"Claude"`, `"OpenAI"`, `"Gemini"`, `"Grok"`, `"Google (Free)"`, `"Google Translate"`, `"DeepL"`, `"Microsoft Translator"`.
  - `AIOperation`: `"translate"`, `"grammarFix"`, `"rewrite"`, `"explain"`, `"screenTranslate"`, `"magic"`.
  - Dates are JSON numbers: `f64` seconds since 2001-01-01T00:00:00Z (add 978307200 for Unix epoch).
  - UUIDs are written uppercase and read case-insensitively.
  - `history.json` / `usage.json` use the envelope v2 `{ "version": 2, "items": [...], "deleted": [{"id","at"}], "clearedBefore": <date> }`.
  - UI and error text use `display_name()`, never the raw value.
- Prompt texts are copied verbatim from the macOS `Core/PromptBuilder.swift` (token `{{targetLanguage}}`) and are never localized.
- No external network in tests; loopback mock servers in `tests/` are allowed. Live tests are `#[ignore]` and never run in CI. See "Live provider checks".
- No secrets or API keys in logs, fixtures or issues.
- `unsafe` is allowed only under `crates/lingopop-platform/src/windows/` and `src/macos/` (crate-level `deny(unsafe_code)`, `// SAFETY:` on every block); core stays `forbid(unsafe_code)`.
- `DevPlaintextProtector` is gated by `cfg(any(test, feature = "dev-plaintext"))`; the feature is off by default. Native Windows uses DPAPI and native macOS always uses MacProtector.

## Platform checks

- Default run (`cargo test --workspace --locked`, every CI leg): pure algorithm tests on fakes, hotkey mapping, clamp, OCR selection, plus on Windows the DPAPI tests, `native_bundle_constructs`, the login-item registry tests (run by default under a throwaway `HKCU\Software\LingoPopTest\...` key) and the `ocr_*` tests (skip-aware: no language pack prints `skipped: OcrUnavailable`). On macOS the monitors test of the dev implementation runs; `mac_clipboard_roundtrip_text` is `#[ignore]` because it touches the real pasteboard.
- Rule: any test that needs an interactive desktop (real clipboard, foreground window, cursor, hotkey delivery, screen capture) is `#[ignore = "needs interactive desktop"]` and lives in `tests/windows_smoke.rs`; the one exception is the input-driven overlay tests (`#[ignore = "needs interactive desktop, input-driven"]`), which live in `tests/windows_desktop_input.rs`. All hotkey desktop tests stay ignored together with the other desktop tests.
- CI: the Windows leg runs them in a dedicated required step, `cargo test -p lingopop-platform --locked --test desktop_probe --test windows_smoke --test foreground_helper -- --ignored --nocapture --test-threads=1`. The probe on `windows-latest` printed `PROBE interactive=true clipboard=ok hotkey=ok sendinput=1` (WinSta0, one 1024x768 monitor). The overlay lifecycle / cancel / virtual-origin smoke tests and the last-foreground tracker tests run in this required step. The input-driven overlay tests (`tests/windows_desktop_input.rs`) run in the separate optional step `Windows input-driven desktop tests` (`continue-on-error`). If the runner image ever loses its desktop, re-mark the required step `continue-on-error: true`.
- By hand on a Windows machine with a desktop: `cargo test -p lingopop-platform --test windows_smoke --test foreground_helper -- --ignored --nocapture --test-threads=1` (the helper target must be built too; it exits 0 at once when started without `--window`).
- macOS owner-run real-Vision tests (`cargo test -p lingopop-platform --locked --test macos_ocr --test macos_dev -- --ignored`): `macos_ocr::{a_blank_image_is_a_real_empty_result_not_an_error, the_same_image_can_be_recognized_twice, recognition_runs_off_the_main_thread, rotated_text_is_recognized_by_the_accurate_level}` and `macos_dev::native_bundle_ocr_is_a_real_empty_recognition_without_permission_or_topology`; the default run keeps `macos_ocr::vision_reads_the_fixture` as the one real-Vision smoke test.
- macOS dev implementation: `send_copy` needs Accessibility permission (System Settings, Privacy & Security, Accessibility, for the terminal or the built app); without it `send_copy` returns `PermissionDenied(Accessibility)`.
- Not verified by CI: real focus behaviour, Replace into real apps, elevated targets (UIPI), mixed-DPI and multi-monitor capture, taskbar on every edge, Excel / Word / image clipboard formats after a capture, console apps where Ctrl+C does not copy, a hung clipboard owner and OCR with no language pack. These are checked by hand on a Windows machine before a release and recorded in the PR; there is no committed checklist file.

## Live provider checks

The live tests in `crates/lingopop-core/tests/live.rs` send real requests to the provider APIs. The owner runs them on a Mac with `scripts/live-tests.sh` before a release or after a provider change. They are never run in CI (all `#[ignore]`), and a plain `cargo test` does not run them. A provider whose variable is unset is skipped (`skipped: <VAR> not set`); with no variables set no request is sent.

| Test | Environment variable(s) |
|---|---|
| `live_claude`, `live_openai`, `live_gemini`, `live_grok` | `LINGOPOP_LIVE_CLAUDE_KEY`, `LINGOPOP_LIVE_OPENAI_KEY`, `LINGOPOP_LIVE_GEMINI_KEY`, `LINGOPOP_LIVE_GROK_KEY` |
| `live_google_cloud` | `LINGOPOP_LIVE_GOOGLE_CLOUD_KEY` (+ optional `LINGOPOP_LIVE_GOOGLE_CLOUD_REFERER`) |
| `live_deepl` | `LINGOPOP_LIVE_DEEPL_KEY` |
| `live_microsoft` | `LINGOPOP_LIVE_MICROSOFT_KEY` (+ optional `LINGOPOP_LIVE_MICROSOFT_REGION`) |
| `live_google_free` | `LINGOPOP_LIVE_GOOGLE_FREE=1` (unofficial endpoint, no key) |

Optional model override: `LINGOPOP_LIVE_<P>_MODEL` with `<P>` = `CLAUDE`, `OPENAI`, `GEMINI`, `GROK`, `GOOGLE_CLOUD`; the default is the `default_providers()` model. Every provider translates `"Good morning, my friend."` to Ukrainian (non-empty, differs from the input, contains a Cyrillic character); the LLM providers also run GrammarFix and the vision path on `fixtures/vision/hello.png`.

- Keys are read from the environment and never printed, logged or committed, not even on failure.
- A live test that fails after a provider API change means: update the Swift-parity facts (the macOS provider sources) and the mock tests first, then the provider.

## Mac compatibility

Compatibility fixtures are generated by `scripts/mac-fixtures/run.sh` and are never hand-edited.

## Branching

Until Phase 1 Task 12 is done, commits go directly to `main`. Afterwards `main` is PR-only (branch ruleset) with the required checks `build-and-test` and `CodeRabbit`, one approving review and resolved review threads; direct pushes are rejected.
